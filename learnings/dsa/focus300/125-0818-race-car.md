# Focus300 125: LeetCode 818 - Race Car

**Source:** [LeetCode 818](https://leetcode.com/problems/race-car/)  
**Difficulty:** Hard  
**Pattern:** shortest instruction sequence via binary-distance DP

## Exact contract

A car starts at position `0` with speed `+1`. Instruction `A` adds the current
speed to the position and doubles the speed. Instruction `R` keeps the position
and changes the speed to `-1` when positive or `+1` when negative. For a
positive target, return the minimum instruction count that reaches it.

## First principles

After `k` consecutive accelerations, the car is at `2^k - 1`. Let `k` be the
first such run reaching or passing a remaining positive distance.

An optimal plan either overshoots with `k` accelerations and reverses, or stops
at `2^(k-1)-1`, reverses, drives backward for `m < k-1` accelerations, reverses
again, and solves the smaller remaining distance. These cases cover the first
direction changes of every optimal plan.

## Cases that decide correctness

- Targets `2^k - 1` need exactly `k` accelerations.
- Overshooting can be shorter than reversing before the target.
- The first reverse changes direction but does not move the car.
- Zero backward accelerations is a valid undershoot case.
- Every DP transition must reduce the remaining positive distance.

## Brute force: BFS over position and signed speed

```python
from collections import deque


def race_car_brute(target: int) -> int:
    if type(target) is not int or not 1 <= target <= 10_000:
        raise ValueError("target must be an integer between 1 and 10,000")

    queue = deque([(0, 1, 0)])
    visited = {(0, 1)}
    while queue:
        position, speed, instructions = queue.popleft()
        if position == target:
            return instructions
        next_states = (
            (position + speed, speed * 2),
            (position, -1 if speed > 0 else 1),
        )
        for state in next_states:
            if state not in visited:
                visited.add(state)
                queue.append((state[0], state[1], instructions + 1))
    raise RuntimeError("every positive target is reachable")
```

BFS is exact but explores many irrelevant positions and speeds.

## Better insight: reason between direction changes

Maximal acceleration runs have geometric distances. Enumerating where the first
one or two reversals occur gives smaller copies of the same distance problem.

## Expert solution: memoized overshoot/undershoot recurrence

```python
from functools import cache


def race_car(target: int) -> int:
    if type(target) is not int or not 1 <= target <= 10_000:
        raise ValueError("target must be an integer between 1 and 10,000")

    @cache
    def solve(distance: int) -> int:
        if distance == 0:
            return 0
        acceleration_count = distance.bit_length()
        full_distance = (1 << acceleration_count) - 1
        if full_distance == distance:
            return acceleration_count

        best = acceleration_count + 1 + solve(full_distance - distance)
        forward_count = acceleration_count - 1
        forward_distance = (1 << forward_count) - 1
        for backward_count in range(forward_count):
            backward_distance = (1 << backward_count) - 1
            position = forward_distance - backward_distance
            remaining = distance - position
            instructions = forward_count + 1 + backward_count + 1 + solve(remaining)
            best = min(best, instructions)
        return best

    return solve(target)
```

The recurrence enumerates every possible first reversal geometry while caching
each smaller remaining distance once.

**Complexity:** `O(target log target)` time and `O(target)` memo space in the
standard bound; only reached distances are stored.
