# Focus300 076: LeetCode 502 - IPO

**Source:** [LeetCode 502](https://leetcode.com/problems/ipo/)  
**Difficulty:** Hard  
**Pattern:** capital sweep with a maximum-profit heap

## Exact contract

Given nonnegative project profits, required capital, initial capital, and a
maximum project count, choose at most that many distinct projects. A project is
available when current capital meets its requirement, and completing it adds
its profit. Return the maximum final capital.

## First principles

At one decision point, choosing the largest profit among currently affordable
projects can only increase the set of projects affordable later. Sort projects
by required capital, sweep newly affordable projects into a max-heap, and take
one best profit per round.

## Cases that decide correctness

- A project can be selected at most once.
- Fewer than the allowed count may be completed when none is affordable.
- Equal capital requirements all become available together.
- Zero-profit projects never improve capital but remain valid input.
- Capital changes only after a project is selected.

## Brute force: try every affordable project sequence

```python
def maximize_capital_brute(
    project_limit: int,
    initial_capital: int,
    profits: list[int],
    capital: list[int],
) -> int:
    if (
        project_limit < 0
        or initial_capital < 0
        or len(profits) != len(capital)
        or any(value < 0 for value in profits + capital)
    ):
        raise ValueError("invalid project data")

    def search(remaining: tuple[int, ...], steps: int, current: int) -> int:
        answer = current
        if steps == project_limit:
            return answer
        for offset, project in enumerate(remaining):
            if capital[project] <= current:
                answer = max(
                    answer,
                    search(
                        remaining[:offset] + remaining[offset + 1 :],
                        steps + 1,
                        current + profits[project],
                    ),
                )
        return answer

    return search(tuple(range(len(profits))), 0, initial_capital)
```

This explores up to `O(n^k)` project sequences.

## Better transition: separate availability from choice quality

Sorting by capital makes availability a one-way sweep. A max-heap then answers
the independent question: which already available project adds the most
capital now?

## Expert solution: sorted requirements plus max-heap

```python
import heapq


def maximize_capital(
    project_limit: int,
    initial_capital: int,
    profits: list[int],
    capital: list[int],
) -> int:
    if (
        project_limit < 0
        or initial_capital < 0
        or len(profits) != len(capital)
        or any(value < 0 for value in profits + capital)
    ):
        raise ValueError("invalid project data")

    projects = sorted(zip(capital, profits))
    available: list[int] = []
    index = 0
    current = initial_capital
    for _ in range(project_limit):
        while index < len(projects) and projects[index][0] <= current:
            heapq.heappush(available, -projects[index][1])
            index += 1
        if not available:
            break
        current -= heapq.heappop(available)
    return current
```

Replacing any affordable chosen project with the maximum-profit affordable
project cannot reduce current or future capital, so an optimal sequence starts
with the greedy choice. Repeating the exchange argument proves every heap pop
is safe.

**Complexity:** `O(n log n + k log n)` time and `O(n)` space.
