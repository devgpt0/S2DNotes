# Focus300 159: LeetCode 15 - 3Sum

**Source:** [LeetCode 15](https://leetcode.com/problems/3sum/)  
**Difficulty:** Medium  
**Pattern:** sorting, duplicate skipping, and two pointers

## Exact contract

Return every distinct value triplet `[a, b, c]` obtainable from three distinct
indices such that `a + b + c == 0`. The output must not contain duplicate
triplets; triplet and result order are otherwise unrestricted.

## First principles

After sorting a copy, fix the first value. The other two values must sum to its
negation, and their sum changes monotonically as left or right moves. Skip equal
fixed values and, after finding a triplet, skip equal pointer values so each
value combination is emitted once.

## Cases that decide correctness

- Three equal zeros produce exactly one triplet.
- Repeated values may still be required, such as `[-1, -1, 2]`.
- Distinct indices, not distinct values, satisfy the selection rule.
- Sorting a copy preserves the caller's input.
- Once the fixed value is positive, no later triplet can sum to zero.

## Brute force: enumerate index triples and deduplicate values

```python
def three_sum_brute(numbers: list[int]) -> list[list[int]]:
    if type(numbers) is not list or not 3 <= len(numbers) <= 3_000:
        raise ValueError("numbers length must be between 3 and 3,000")
    if any(
        type(value) is not int or not -100_000 <= value <= 100_000 for value in numbers
    ):
        raise ValueError("numbers must be integers in the source range")

    triplets: set[tuple[int, int, int]] = set()
    for first in range(len(numbers)):
        for second in range(first + 1, len(numbers)):
            for third in range(second + 1, len(numbers)):
                values = (numbers[first], numbers[second], numbers[third])
                if sum(values) == 0:
                    ordered = sorted(values)
                    triplets.add((ordered[0], ordered[1], ordered[2]))
    return [list(values) for values in sorted(triplets)]
```

This costs `O(n^3)` time and up to `O(n^2)` result-set space.

## Better insight: fixing one sorted value turns the rest into 2Sum

The sorted pair sum is monotone, so each fixed index needs one linear inward
scan instead of a nested pair enumeration.

## Expert solution: sorted two-pointer sweep

```python
def three_sum(numbers: list[int]) -> list[list[int]]:
    if type(numbers) is not list or not 3 <= len(numbers) <= 3_000:
        raise ValueError("numbers length must be between 3 and 3,000")
    if any(
        type(value) is not int or not -100_000 <= value <= 100_000 for value in numbers
    ):
        raise ValueError("numbers must be integers in the source range")

    ordered = sorted(numbers)
    answer: list[list[int]] = []
    for first in range(len(ordered) - 2):
        if first > 0 and ordered[first] == ordered[first - 1]:
            continue
        if ordered[first] > 0:
            break
        left = first + 1
        right = len(ordered) - 1
        while left < right:
            total = ordered[first] + ordered[left] + ordered[right]
            if total < 0:
                left += 1
            elif total > 0:
                right -= 1
            else:
                answer.append([ordered[first], ordered[left], ordered[right]])
                left_value = ordered[left]
                right_value = ordered[right]
                while left < right and ordered[left] == left_value:
                    left += 1
                while left < right and ordered[right] == right_value:
                    right -= 1
    return answer
```

Every pointer move discards sums that are provably too small or too large, and
the duplicate skips give one output per value triplet.

**Complexity:** `O(n^2)` time and `O(n)` space for the sorted copy, excluding
the output.
