# 21 - Spring AI Fundamentals and ChatClient

These notes target Spring AI 2.0.0 with Spring Boot 4.1.0, as generated by the official Spring Initializr.

## Beginner Meaning

Spring AI gives Java interfaces and Spring Boot configuration for calling AI models. `ChatClient` is the main fluent API: build a prompt, call the model, and receive text or a typed result.

Model output is generated, not guaranteed truth. Validate it before using it in business decisions.

## Dependency Management

```xml
<properties>
    <spring-ai.version>2.0.0</spring-ai.version>
    <!-- Result: Spring AI modules use the official stable 2.0.0 BOM. -->

# Result: startup receives credentials/model from deployment configuration, not source control.
```

## `ChatClient`

Spring AI auto-configures a prototype `ChatClient.Builder` and retains observability/customizers when it is injected.

```java
@Service
final class AssistantService {
    private final ChatClient chatClient;

    AssistantService(ChatClient.Builder builder) {
        chatClient = builder
                .defaultSystem("Answer concisely and state uncertainty.")
                .build();
    }

    String answer(String question) {
        if (question == null || question.isBlank()) {
            throw new IllegalArgumentException("question must not be blank");
        }
        return chatClient.prompt()
                .user(question)
                .call()
                .content();
        // Result: returns model-generated text; content is nondeterministic and untrusted.
    }
}
```

## Streaming

```java
Flux<String> tokens = chatClient.prompt("Explain Java records")
        .stream()
        .content();
System.out.println(tokens != null);
// Output: true
// Tokens arrive asynchronously and require cancellation/backpressure handling.
```

## Production Rules

- set request deadlines and concurrency limits
- cap prompt, response, and conversation size
- validate model output before business use
- never place secrets in prompts
- treat model responses as untrusted input
- record token/cost/latency metrics without sensitive content
- define acceptable fallback behavior
- pin model identifiers through configuration and evaluate before changes
